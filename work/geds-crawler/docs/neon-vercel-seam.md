# Neon + Vercel public read-store seam

The public runtime is same-origin and GET-only. Vercel serves the Career Atlas
frontend and its API adapter uses a Neon connection with a SELECT-only role.
The crawler, canonical master, import credential, and control plane remain
private.

## Free-only provisioning gate

Use Vercel's native Neon integration. Before creating a resource, the
integration screen or CLI response must explicitly show the Free / $0 plan.
If the only available path asks for a paid plan, billing activation, or a
card, stop. Do not create the resource or continue with deployment.

The native integration should connect with an environment-variable prefix so
its generated names are easy to audit. Values must never be printed, pulled
into a local file, or exposed through a `NEXT_PUBLIC_`/`VITE_` variable.

After connection, record only the key names and target environments. The
runtime contract is:

| Key | Purpose | Exposure |
| --- | --- | --- |
| `GEDS_PUBLIC_DATABASE_URL` | pooled Neon URL for the Vercel read-only role | Vercel runtime only |
| `GEDS_PUBLIC_DATABASE_URL_UNPOOLED` | private operator/import connection | importer only; never public runtime |
| `GEDS_PUBLIC_PROJECTION_SCHEMA` | `geds_public` | non-secret configuration |
| `GEDS_PUBLIC_ACTIVE_POINTER` | `active_projection` | non-secret configuration |

The exact names generated by the native integration must be checked after
connection; this table is the application contract, not a claim about the
provider's secret values.

## Import contract

1. Export a complete canonical snapshot to the versioned SQLite projection.
2. Validate the manifest, allow-list, privacy boundary, counts, and hash.
3. Stage the release under `geds_public` using `sql/public_projection_postgres.sql`.
4. Run a GET-only smoke test against the staged release.
5. Update the singleton `active_projection` pointer in one transaction.

`public_projection_import.py` makes stages 3–5 separate operations. Staging
never activates a release, and activation is rejected unless the same
coordinator has completed staging and smoke. The full crawl must finish and
produce a complete quality status before the first public import; the current
partial overlay is not eligible.

The Neon runtime role receives `USAGE` on `geds_public` and `SELECT` on its
tables only. Create the login role and its secret in Neon/Vercel, not in this
repository. The checked-in SQL contains only the grants contract.

## Vercel linkage gate

The intended Vercel project is `geds-career-atlas` with the frontend root at
`work/geds-career-atlas`. Keep `/api` same-origin so the browser does not need
database credentials or a cross-origin endpoint. Do not deploy until the
project linkage, generated key names, read-only role, projection schema, and
contract smoke test are all recorded.
